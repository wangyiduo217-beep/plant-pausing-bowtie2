# 生产流程来源与验证边界

记录日期：2026-09-12。

本仓库是依据植物 pausing 项目已运行的处理流程整理的**便携 Bowtie2 实现**。原生产环境另有下载校验、参考构建、队列迁移、资源租约和持续监控等设施。除非本仓库具体文件已实现并验证相同能力，不应认为这些设施会随 Bowtie2 命令自动提供。

本记录不包含原始测序文件、FASTQ、BAM、参考基因组、服务器连接信息、账号或认证材料。公开项目编号与方法参数用于追踪方法，不代表仓库托管了对应数据。

## 稳定生产参数

| 环节 | 2026-09-12 使用的参数或行为 |
|---|---|
| SRA 转换 | `fasterq-dump --split-3`，额外未配对输出先人工核对 |
| 常规剪切 | Cutadapt `-q 20 --max-n 0.1`，最终最短 25 nt；接头和 poly(A) 按项目配置 |
| 接头匹配 | 常规 `-O 8 -e 0.1`；GSE181598 的 A10 使用独立最短重叠 10 nt |
| NEXTflex | 先剪接头、最短 33 nt；随后每个 mate 两端各剪 4 nt、最短 25 nt |
| rRNA | Bowtie2 `--very-sensitive`；双端仅按 concordant pair 过滤，不是穷尽去污染 |
| 基因组 | Bowtie2 `--very-sensitive --end-to-end`；双端 `--no-mixed --no-discordant -X 1000 --dovetail` |
| 排序 | `samtools sort -m 1G`，分别检查比对和排序退出状态 |
| 索引 | CSI，`samtools index -c` |
| 高可信 BAM | `samtools view -b -q 20 -F 2820`；不做坐标去重，保留参考内细胞器序列 |
| 基本质控 | Cutadapt JSON、FastQC、`flagstat`、`idxstats`、BAM `quickcheck` |

GSE181488 在生产环境使用 HISAT2，不属于本仓库的 Bowtie2 分支。原生产配置出现 HISAT2，不能据此声称本仓库已经实现或验证 HISAT2。

## 已核对的项目特异规则

| 项目 | 生产配置与证据边界 |
|---|---|
| GSE181598 | 使用内部 `A{10};min_overlap=10` 作为 3′ 接头，不启用 `--poly-a`。两个 WT 样本的原始探针显示实验性 poly(A) 后仍有非 A 序列；匹配抽样支持该修正，两个全量样本已重跑并检查 BAM。该规则不能自动推广到其他项目。 |
| GSE117014 | 使用 `TGGAATTCTCGGGTGCCAAGG` 加 `--poly-a`，不做固定 5′ 剪切。依据观察到的 3′ 接头读穿修正；两个标准 WT 样本已完成该配置下的全量分析。体外 run-on 条件对照仍需保持单独分组。 |
| GSE95301 | 保持 `--poly-a` 尾处理。匹配抽样比较中，套用内部 A10 会减少高可信核基因组记录，因此没有把 GSE181598 的规则迁移到此项目。抽样比较不等于所有潜在协议问题已经排除。 |
| GSE178276 | 使用 NEXTflex 配置：R1 接头 `TGGAATTCTCGGGTGCCAAGG`，R2 接头 `GATCGTCGGACTGTAGAACTCTGAAC`，随后两端各剪 4 nt；不启用 `--poly-a`。建库协议已核对。一个生物学样本可能对应多个 SRR。 |
| PRJNA788565 | 按 NEXTflex v3 协议配置上述接头与两端 4 nt 剪切。仓库整理时首次转换后的全量原始探针审核尚未完成；该配置的来源不能表述为三个样本的全量结果均已验证。 |
| GSE83108 | 使用 R1 接头 `AGATCGGAAGAGCACACGTCTGAACTCCAGTCAC`，不启用 `--poly-a`，无固定随机碱基剪切。仅针对纳入的普通 GRO-seq。 |
| GSE128698、GSE109974、GSE54166 | 当前为 `--poly-a`，不额外指定接头或固定随机碱基剪切；应保留各项目独立配置，未来修改需要单独证据。 |

实际可执行配置及其变更应与本记录一起审查；配置名称相同不等于实验协议相同。

## 2026-09-12 并行优化记录

生产机器有 48 个物理核心、96 个逻辑 CPU，且为共享服务器。原队列每次完成一个 SRR 的所有阶段后才进入下一个，限制了整体吞吐。新生产调度允许最多 4 个样本交错推进；阶段申请受 CPU 与内存预算限制。

| 资源或阶段 | 新生产设置 |
|---|---:|
| CPU 调度预算 | 80 |
| 内存调度预算 | 160 GiB |
| 实际可用内存下限 | 32 GiB |
| SRA 转换 | 每个 8 线程，同时最多 1 个 |
| Cutadapt | 每个 8 线程 |
| rRNA 过滤 | 新任务每个 24 线程，原为 8 |
| 基因组比对 | 每个 16 线程 |
| BAM 排序 / SAMtools 质控 | 每个 4 线程 |
| 原始 FASTQ 压缩 | 每个 8 线程 |

CPU 数值是阶段调度预算，包含部分辅助进程余量，不是操作系统的硬配额。磁盘准入还有空间预留检查。机械存储在一路转换与既有过滤任务同时运行时，两次约 12 秒测量的繁忙度为 88.94% 和 92.71%，因此保持单转换通道，让转换与其他样本的计算阶段重叠。

同一批 **SRR14825454 前 100,000 对 clean reads**、同一 rRNA 索引和参数的小测试结果：

| rRNA 线程数 | 实测耗时 | 保留 pair 数 |
|---:|---:|---:|
| 8 | 12.08 秒 | 16,939 |
| 16 | 6.32 秒 | 16,939 |
| 24 | 4.47 秒 | 16,939 |

三次保留的 read 名单 SHA-256 一致。测试每档仅一次，使用已解压的小输入和已缓存参考；全量生产输入为 gzip，且会有其他任务争用资源。因此该测试支持此次线程调整，但不构成全流程固定 2.70 倍提速、所有样本一致性或 BAM 字节完全一致的保证。

生产并行改造另做了 42 个 SRR 的新旧命令模拟比较，除 rRNA 线程数外保留科学参数；也检查了阶段资源互斥、逐样本锁、启动记录与旧任务迁移。这些检查针对**生产队列改造**，不是对本仓库提取代码的全量测序数据验收。

## 本仓库的验证边界

仓库测试应证明参数生成、输入保护、成对数据处理、状态判定和失败传播符合预期。小型真实工具测试与模拟命令测试的范围应分别披露。未在本仓库实现上重新处理完整 SRR 的项目，不应被表述为“本仓库全量验证通过”。

以上段落记录的是 2026-09-12 的生产状态。到 2026-09-19，纳入标签的 BAM 和三物种正窗口 y 表已经完成；实际标签算法、样本清单和结果见 [GRO-seq y 标签构建流程](groseq-y-label-generation.md)。仓库仍不托管大体积 BAM 或标签数据，并且尚未生成完整负样本、训练深度学习模型或形成所有科研质控结论。
